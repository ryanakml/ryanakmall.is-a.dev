**Enter only after Checkpoint B approval.** **Exit:** complete local website ready for technical and visual QA.

## Product scope

Determine pages and sections from approved identity, content and audience needs. Possible elements: introduction, selected work, focused case studies, About, open-source contribution evidence, writing/notes and contact. **These are options, not a checklist.** Avoid empty sections or unverified accomplishments. Show substantive engineering ability through truthful project problems, decisions, artifacts and verified evidence—not decorative tech badges.

Use minimal viable architecture, semantic HTML, responsive design, accessible interactions, proper font/image licensing, purposeful motion and optimized assets. Build useful SEO/social metadata and good mobile performance. Use Taste Skill's relevant production-design guidance. Any imported Motion Primitives or 21st.dev component must have a documented purpose, license, dependency and accessibility rationale.

Keep public claims synchronized with `state/facts.md`; seek permission before inspecting professional profiles/repos that were not explicitly authorized. Keep documentation short and practical. Produce a working local production build, then load `phases/05-qa-launch.md`.
