# Personal Internet Home — Operating Contract

This is a **new, identity-led personal website**, not a redesign. The website must feel elegant, distinctive, credible, and human. Its owner is a software engineer, but the site must not default to developer-portfolio stereotypes.

## Non-negotiable boundaries

- **Fresh workspace only.** Do not search, read, import, or infer from parent/sibling directories, old portfolio repositories, past mockups, legacy briefs, previous chats, unrelated local files, or private documents. Tool/skill installation files and official public documentation are permitted for tool operation. Ask before expanding the scope.
- **Truthful identity.** Learn biography from the user's answers. Research the user's public profiles/projects only after explicit authorization. Never fabricate education, jobs, clients, metrics, project outcomes, or testimonials.
- **No predetermined aesthetic.** Discover the person first; combine approved identity with outstanding design research. Avoid generic terminal/neon/dashboard/SaaS portfolio clichés without banning any design element categorically.
- **Mandatory Taste Skill for visual work.** Verify the installed `design-taste-frontend` instructions and apply its actual design/inspection workflow to both prototypes and final refinement. If unavailable, resolve before beginning visual implementation; identity interviews can continue.
- **Evidence over assertion.** Real browser render/screenshots are required before claiming visual QA; respect asset/font/component licenses. Never claim an unavailable tool was used.
- **Two human gates.** Checkpoint A: identity/positioning approval before final art direction. Checkpoint B: user chooses between two working, browser-reviewed prototypes before production build. No assumed approval.
- **No public launch without approval.** No domain purchase, public push, or live deployment without explicit permission.

## Single source of truth and priority

Follow applicable higher-priority instructions, then explicit user decisions from this project, then this operating contract, then the *current phase brief*, then tool recommendations. External research and skills inform design but cannot override the user's approved identity or design. If a real conflict remains, surface it concisely.

`state/decisions.md` records the active phase, approvals, and settled choices. Do not treat speculative entries as approved. Update it at each checkpoint and after material decisions. Keep public-facing claims grounded in `state/facts.md`.

Private interview/state files are intentionally omitted from the public repository. When they are absent, use `docs/decisions.md` for the approved project state and `docs/evidence-and-assets.md` for public evidence and provenance. Continue from the active phase recorded there; do not restart discovery or infer new approvals.

## Progressive disclosure

Read only `phases/<active-phase>.md` for the current work. **Do not preload every phase.** Start at `phases/01-discovery.md`. Read the next phase only when its prerequisites are met. Keep notes compact; do not turn research documents into the deliverable.

- `01-discovery.md` → Checkpoint A
- `02-art-direction.md` → two distinct concepts, then advance to prototypes
- `03-prototypes.md` → Checkpoint B
- `04-production.md` → final implementation after B
- `05-qa-launch.md` → QA, preview and authorized launch

## Team and execution

Lead Codex agent is the **only integration owner**. Four specialist roles are available as needed: (A) Identity & Narrative Architect, (B) Visual Researcher, (C) Taste Art Director, (D) Technical Architect. Spawn selectively based on dependencies; research specialists should be read-only. Do not allow simultaneous writes to overlapping files. If subagents are unsupported, perform the roles sequentially and state that clearly.

Communicate naturally in Indonesian. Ask focused identity questions in small batches; no giant survey. Explain consequential recommendations and tradeoffs without overreporting. Prioritize working artifacts over long documentation.
